# Чек-лист организатора

Для Дмитрия. Всё, что делаешь ты, а не участники.

---

## Накануне (30-40 минут)

### 1. Собрать ники GitHub
Попроси всех завести аккаунт и прислать ник заранее. Это самая частая
задержка на старте: без ника код не скачается.

### 2. Выдать доступ к репозиториям

```bash
bash admin/invite.sh ник1 ник2 ник3
```

или списком из файла (по нику в строке):

```bash
bash admin/invite.sh -f nicks.txt
```

Выдаётся право `push` на **MosForum-DayTrack**, **MosForum-ERP**,
**MosForum-Tasker**. Репозиторий `applications-moderator` не выдаётся.
Участникам придёт приглашение на почту - им надо его принять.

### 3. Включить согласование выката

```bash
bash admin/protect.sh          # посмотреть, что изменится
bash admin/protect.sh --apply  # применить
```

После этого в главную ветку можно попасть только через pull request с твоим
одобрением. Ты сам при необходимости мерджишь через `gh pr merge --admin`.

**Что меняется в твоих репозиториях:**

| Репозиторий | Было | Станет |
|---|---|---|
| MosForum-DayTrack `main` | pull request нужен, одобрений 0 | pull request + **1 одобрение**, проверка `checks` сохраняется |
| MosForum-ERP `main` | защиты нет | pull request + 1 одобрение |
| MosForum-Tasker `corp-master` | защиты нет | pull request + 1 одобрение |

Откатить можно в настройках репозитория на GitHub (Settings → Branches).

### 4. Предупредить про загрузки
Docker Desktop и Cursor - это суммарно около 3 ГБ на человека. Если все
качают одновременно с одного Wi-Fi, старт растянется. Варианты: попросить
запустить `setup.sh` дома накануне, или раздать Docker с флешки.

## Утром, на старте

### Активация Claude Code
Каждый участник пришлёт тебе ссылку вида `https://claude.ai/oauth/authorize?...`.
Открываешь её в браузере под своим аккаунтом, подтверждаешь, пишешь
«активировал».

**Заложи на это время.** Ссылка живёт около 10 минут, а ты один. При десяти
участниках это очередь. Практично: попроси присылать ссылки волнами по 3-4
человека, а не всем разом.

### ⚠️ Про общую подписку - прочитай до старта

Все участники будут работать **от одной твоей подписки**. Это значит:

- **Лимиты общие.** Десять человек на Opus с контекстом 1M исчерпают дневной
  лимит в разы быстрее, чем ты один. С большой вероятностью упрётесь в потолок
  ещё до обеда.
- **Если упрётесь** - самое быстрое лечение: попросить всех переключиться на
  модель попроще командой `/model` (выбрать Sonnet). Это снимает нагрузку в
  несколько раз и почти не бьёт по качеству на задачах хакатона.
- **Надёжная альтернатива**, если успеваешь настроить: завести командный план
  Claude и раздать каждому своё место. Тогда лимиты у каждого свои, и очереди
  с активацией ссылок тоже не будет.

Я не знаю, сколько именно лимита у твоей подписки и на скольких человек его
хватит - это видно только по факту. Но риск реальный, и лучше решить заранее,
чем в разгар хакатона.

## Что участники получают одинаково

- Правила работы `~/.claude/CLAUDE.md` - те же, что у тебя, минус твои личные
  проектные детали
- 38 скиллов: дизайн (impeccable, frontend-design, high-end-visual-design,
  анимация), документы (pptx, docx, xlsx, pdf), тестирование, mcp-builder
- Плагины **superpowers** (brainstorming, планы, TDD, systematic-debugging)
  и **playwright** (проверка в браузере)
- Права инструментов, модель `opus[1m]`, светлая тема, полноэкранный режим

### Чего у них не будет и почему

| Что | Почему |
|---|---|
| Плагины figma, codex, кибербез | Нужны отдельные аккаунты (Figma, ChatGPT) или сильно раздувают список навыков. Ставятся флагом `--full`, если нужно |
| Коннекторы Gmail, Google Drive, Adobe, higgsfield | Привязаны к твоему личному аккаунту Claude, перенести их на чужую машину нельзя |
| Звуки и статус-строка на Windows | Сделаны под macOS. На работу не влияет |
| Доступ к боевым серверам и базам | Намеренно. Хакатон идёт на локальной базе с демо-данными |
